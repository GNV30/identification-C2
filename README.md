# C2 Metadata Detector

Небольшой исследовательский проект для выявления Command-and-Control каналов в зашифрованном сетевом трафике по метаданным потоков. Проект не расшифровывает TLS и не анализирует полезную нагрузку: вместо этого он использует признаки, которые обычно доступны в NetFlow/Zeek/Suricata-логах.

## Идея

C2-каналы часто выглядят как обычные HTTPS-соединения, но у них остаются поведенческие следы:

- регулярные короткие обращения к одному узлу;
- малый объем данных при большом количестве сессий;
- схожие интервалы между соединениями;
- нетипичное соотношение входящих и исходящих байтов;
- повторяемость направлений `src_ip -> dst_ip:dst_port`.

`c2meta` агрегирует сетевые потоки по направлениям связи, рассчитывает признаки и присваивает риск-оценку. Такой подход подходит для учебного проекта, первичного threat hunting и демонстрации идеи из материалов по выявлению C2 в зашифрованном трафике.

## Возможности

- чтение CSV с метаданными сетевых потоков;
- извлечение поведенческих признаков без доступа к payload;
- эвристический скоринг подозрительных каналов;
- обучение простой ML-модели на размеченном CSV;
- CLI-команды для анализа, обучения и сохранения отчетов;
- тесты для ключевой логики.

## Быстрый старт

```bash
python -m venv .venv
.\.venv\Scripts\activate
pip install -e ".[dev]"
```

Запуск анализа на примере:

```bash
c2meta scan data/sample_flows.csv --top 10
```

Сохранение отчета:

```bash
c2meta scan data/sample_flows.csv --output reports/demo_report.csv
```

Обучение модели на CSV с колонкой `label`:

```bash
c2meta train data/sample_flows.csv --model artifacts/c2_model.joblib
```

Запуск анализа через обученную модель:

```bash
c2meta scan data/sample_flows.csv --model artifacts/c2_model.joblib
```

## Формат входных данных

Минимальный CSV должен содержать колонки:

| Колонка | Описание |
| --- | --- |
| `timestamp` | время начала потока в ISO-формате |
| `src_ip` | IP-адрес источника |
| `dst_ip` | IP-адрес назначения |
| `dst_port` | порт назначения |
| `protocol` | протокол, например `TCP` |
| `duration_ms` | длительность потока в миллисекундах |
| `bytes_out` | байты от источника к назначению |
| `bytes_in` | байты от назначения к источнику |
| `packets_out` | пакеты от источника |
| `packets_in` | пакеты от назначения |
| `label` | опционально: `benign` или `c2` для обучения |

## Пример результата

```text
src_ip       dst_ip         dst_port  flow_count  risk_score  verdict
10.0.0.15    185.199.110.8  443       18          0.88        suspicious
10.0.0.24    34.117.59.81   443       5           0.31        benign
```

## Как работает скоринг

Эвристический детектор учитывает:

- частоту соединений;
- коэффициент вариативности интервалов между потоками;
- средний размер переданных данных;
- отношение исходящего и входящего трафика;
- длительность сессий;
- число уникальных временных интервалов.

Итоговая оценка находится в диапазоне от `0` до `1`. Значения от `0.65` считаются подозрительными по умолчанию. Порог и веса можно настроить в [configs/rules.json](configs/rules.json).

## Ограничения

Это исследовательский инструмент, а не готовая SIEM-система. Он не должен использоваться как единственный источник решения об инциденте. Реальные C2-каналы маскируются под легитимные сервисы, поэтому результаты нужно подтверждать дополнительными источниками: DNS, JA3/JA4, EDR, proxy logs, threat intelligence и контекстом хоста.
